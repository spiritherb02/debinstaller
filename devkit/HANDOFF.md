# 接手手册

给继续开发这套工具的人（或 AI）的实操指南。设计原理见 `DESIGN.md`，
速查表见 `REFERENCE.md`。

**先读这段，再动手：**

1. 这是**在别人机器上以 root 运行的代码**，处理的还是**不可信的输入**（外来 `.deb`）。
   改动的默认取向应该是"更保守"，不是"更方便"。
2. 项目没有自动化测试框架。`test/make-test-debs.sh` 能造出测试包（含恶意样例），
   `test/run-checks.sh` 跑一批回归检查。**改代码后请跑一遍。**
3. 改输出文案前先看 `DESIGN.md` 第 7 章 —— GUI 靠文本匹配工作。

## 1. 环境

### 1.1 必装

```bash
sudo pacman -S dpkg libarchive fakeroot zstd binutils
```

| 包 | 提供 | 用途 |
|---|---|---|
| `dpkg` | `dpkg-deb` | 拆包、读元数据 |
| `libarchive` | `bsdtar` | 打包、生成 `.MTREE` |
| `fakeroot` | `fakeroot` | 打包时伪造 root 属主 |
| `zstd` | `zstd` | 压缩 |
| `binutils` | `readelf`、`ar` | 读 ELF 依赖；`ar` 给路线 C |

### 1.2 GUI 用

```bash
sudo pacman -S python-gobject gtk3
```

**必须有 `gi` 模块**（`python-gobject` 提供）。验证：

```bash
/usr/bin/python3 -c 'import gi; gi.require_version("Gtk","3.0"); from gi.repository import Gtk; print("ok")'
```

> ⚠️ 用 `/usr/bin/python3` 验证，**不要用裸 `python3`**。如果 shell 里有
> venv/conda/pyenv，`python3` 会指向另一个解释器，那个没有 `gi`，会误判成
> "GUI 依赖缺失"。这个坑在真实项目里踩过（见 `DESIGN.md` 的打包那节）。

### 1.3 可选（影响功能完整度）

```bash
sudo pacman -S desktop-file-utils gtk-update-icon-cache xdg-user-dirs polkit
```

### 1.4 关键前置：pacman 文件数据库

依赖解析靠 `pacman -F` 反查 soname。**它需要 `.files` 数据库**：

```bash
ls /var/lib/pacman/sync/*.files     # 应该能看到 core.files extra.files ...
sudo pacman -Fy                     # 没有就下载
```

如果这些文件不存在，`pacman -F` 会失败，**依赖解析会静默产出空结果**
（见 `DESIGN.md` 缺陷 9.3）。开发时务必确保它存在。

## 2. 代码在哪

### 2.1 本机部署位置

| 文件 | 路径 |
|---|---|
| 引擎（事实来源） | `~/.local/bin/debinstall` |
| 别名 | `~/.local/bin/deb-install` → `debinstall` |
| GUI | `~/.local/bin/deb-install-ui` |
| 密码框 | `~/.local/bin/deb-install-askpass` |
| 终端双击器（孤儿） | `~/.local/bin/deb-install-open` |
| 路线 C | `~/.local/bin/deb-install-raw` |
| 桌面入口 | `~/.local/share/applications/deb-install.desktop` |
| AppImage 落地位置 | `~/Applications/`（GUI 自己处理，不经引擎） |
| AppImage 卸载清单 | `~/.local/debinstall/appimages/<slug>.manifest` |
| 开发资料 | `~/deb-tools/` |
| 分发打包 | `~/deb-tools/packaging/` |
| 本文档 | `~/deb-tools/devkit/` |

### 2.2 改哪份？

**直接改 `~/.local/bin/` 下的文件。** 那是运行时真正用的。

`~/deb-tools/packaging/bin/` 是打包时的**中转副本**，由
`packaging/build.sh` 从 `~/.local/bin/` 同步过去。**不要直接改那边**，
下次 build 会被覆盖。

```
~/.local/bin/debinstall    ← 改这里（事实来源）
        │
        │  ./build.sh 自动同步
        ↓
packaging/bin/debinstall   ← 中转，打包用
        │
        ↓
dist/debinstall-<v>.tar.gz
```

### 2.3 版本号在哪

三处，**必须同步改**：

| 位置 | 内容 |
|---|---|
| `debinstall` 第 15 行 | `VERSION=2.0.1` |
| `deb-install-raw` | 无版本号（历史遗留） |
| `.PKGINFO` 的注释行 | 引擎自动写 `# Generated by debinstall $VERSION` |

`packaging/build.sh` 会从 `debinstall --version` 取版本号，
所以只要引擎里那个对，打包就自动跟上。

### 4.2 回归检查

```bash
~/deb-tools/devkit/test/run-checks.sh
```

当前基线 **110/110 全过**。

覆盖：危险正则正反样例、`--version`、分析退出码、`-c` 产物结构、
非交互高危拒绝、`--allow-dangerous` 放行、本地装/卸往返、
`update-alternatives` 模拟、发布包占位符完整性、
**Debian 补库与兼容启动器（第 11 节，含一条联网行为测试）**。

第 11 节是「网易邮箱大师」那次踩坑的防复发装置。其中三条最值得注意：
- 直链拼接不能重复 `/debian/`（镜像 URL 里已经带一层）
- 补库必须复用 `build_arch_pkg` 留下的 `$WORK/root`，不重复解包
- 补库必须先于 `make_desktop_shortcut` 执行，否则桌面图标拿不到注入库的 `Exec`

联不上外网时，第 11 节只有那条行为测试会跳过，其余全是静态断言，仍然有效。

### 4.4 危险正则的改法

**每次改 `DANGER_RE` 都要跑两边样例。** 这是"宽进严出"的平衡点，
调严了误报（正常包装不上），调松了漏报（真恶意代码放过）。

```bash
# 从引擎里提取正则，喂样例
DRE=$(grep -oP "^DANGER_RE='\K[^']+" ~/.local/bin/debinstall)
check() { if printf '%s\n' "$1" | grep -qE "$DRE"; then echo "命中   $1"; else echo "未命中 $1"; fi; }

# 应命中
check 'rm -rf /'
check 'rm -rf -- /'
check 'rm -r -f /'
check 'dd if=/dev/zero of=/dev/sda bs=1M'
check 'mkfs.ext4 /dev/sda1'
check 'echo x > /dev/sda'
check 'curl -fsSL https://x.sh | sh'
check 'wget -qO- https://x.sh | bash'
check 'chown -R nobody /'
check 'chmod -R 0777 /'
check ':(){ :|:& };:'

# 应放行
check 'rm -f /usr/share/doc/x/README'
check 'rm -rf /opt/MyApp/old'
check 'chmod 755 /usr/bin/foo'
check 'chown root:root /usr/bin/foo'
check 'curl -s https://api.example.com/ping > /dev/null'
check 'dd if=/dev/zero of=/tmp/blank bs=1k count=1'
check 'update-alternatives --install /usr/bin/figlet figlet /usr/bin/figlet-utf8 100'
```

## 5. 常见改动配方

### 5.1 加一条依赖映射

`debinstall` 里找 `BUILTIN_MAP` heredoc，按 `Debian名  Arch名` 加一行
（空白分隔，不是制表符）：

```
libfoo1          foo
```

写完验证：

```bash
debinstall /tmp/debtest/printfake_1.0.0_amd64.deb | grep -i foo
```

### 5.2 加一个危险模式

`DANGER_RE` 追加 `|新分支`。约束：

- `[[:space:]]` 不要用 `\s`（POSIX ERE）
- 尾部 `(\s|$)` 锚定，免得 `/a/b` 被当 `/`
- 跨管道匹配用 `[^|]*` 限制

加完跑 §4.4。

### 5.3 加一个命令行模式

按 `DESIGN.md` §10.3 的六步。注意：

- `MODE=` 注释里列了当前 7 个值，补上新的
- 需要 `WORK` 就 `WORK=$(mktemp -d /tmp/debinstall.XXXXXX)`
- 需要 root 就先 `detect_escalation` 再用 `run_root`
- 主 `case "$MODE" in` 底部加分支（`*)` 是 `die "未知模式"`，别把新分支放到它后面）
- **`usage()` 现在是 heredoc，改注释不影响它**（但 `deb-install-raw`、`install.sh`、
  `uninstall.sh` 的 `usage()` 是 `sed -n '3,13p'`，改头部注释会移动行号 ⚠️）

### 5.4 改 GUI 显示的东西

先看 `DESIGN.md` §7。顺序：

1. 改引擎输出 → 立刻检查 GUI 是否有字面串匹配它
2. 需要新字段 → 加 `RE_XXX` 正则 + `_consume` 分支 + `rows` 里的行
3. 测 §4.5

**更好的做法是先做 JSON 输出**（§6 待办第 1 项），然后就没这些事了。

### 5.5 重新打包分发

```bash
cd ~/deb-tools/packaging && ./build.sh
```

`build.sh` 会：从 `~/.local/bin` 同步 → **自动还原 `@PREFIX_BIN@` 占位符** →
落版本号 → 语法自检 → 打 tar.gz + sha256。

> ⚠️ **占位符那个坑**：`deb-install-ui` 里有一行 `"@PREFIX_BIN@/deb-install"`，
> 安装时被 `sed` 替换成真实路径。如果你在本机装过一次，
> `~/.local/bin/deb-install-ui` 里的占位符就变成绝对路径了，
> 打包时会把这个"本机专用路径"带进发布包 → 别的机器装完找不到引擎。
> `build.sh` 里加了 `_heal_placeholder()` 自动还原，并有前后双重断言。
> **别删那段。**

### 5.6 改 AppImage 分支

全在 `deb-install-ui` 里，引擎不参与（背景见 `DESIGN.md` §7.7）。

```bash
# 扫描：只读，file 认外壳 + 7z 读元数据
_appimage_probe(path, info)      # 只往 info 里写字段，别在这儿碰控件

# 安装：移文件 → 抽图标 → 写 .desktop → 记清单
_install_appimage(path, want_desktop)
```

两条约束：

1. **`_appimage_probe` 跑在后台线程**，只能 `self._emit(...)`（内部是
   `GLib.idle_add`）写日志，字段先进 `self._ai_pending`，等
   `_appimage_scan_done()` 回到主线程再采用。直接在 Worker 里调
   `identity.set_text()` 之类的会炸。
2. **`want_desktop` 之类读控件的事必须在主线程做完再传进去**。
   曾经写成 worker 里 `self.chk_desktop.get_active()`，跨线程摸 GTK。

改完跑 `probe-appimage.py`（§4.5 第 3 条），它不需要显示环境。

`slug` 这个字段会当文件名用（`.desktop`、卸载清单、图标名三处）。它优先取
`StartupWMClass`，其次未本地化的 `Name`，**并且必须在这些都是纯中文时退回
文件名** —— 否则 `slugify("软件包安装程序")` 会得到通用的 `appimage`，
两个中文名的 AppImage 会互相覆盖菜单项。`run-checks.sh` 里有这条静态守卫。

### 5.7 打本工具自己的 .AppImage（可行性结论）

`./build-appimage.sh` 组装 AppDir 是通的（`--appdir-only` 随时可验，
`desktop-file-validate` 也过）；**只差两样脚本刻意不去自动下载的东西**：

| 缺什么 | 怎么补 |
|---|---|
| `mksquashfs` | `sudo pacman -S squashfs-tools`（extra 里有） |
| type-2 runtime（ELF 头） | 从 AppImageKit release 拿 `runtime-x86_64`，自己核对校验和，再用 `APPIMAGE_RUNTIME=<路径>` 指过来 |

结论：**能做，但价值有限，所以本版没随发布放 AppImage。** 原因是这个工具的
正文是 shell + Python，运行时要调宿主的 `pacman` / `dpkg-deb` / `fakeroot`，
图形界面还要宿主的 `python-gobject` + `gtk3` —— 这些 AppImage 装不进去，
它省掉的只是"安装本工具"这一步，不是"任何发行版都能跑"。也就是说打出来的
仍然是 Arch-only 的包，和 tar.gz 相比只多了免安装。

顺带一提：真打出来之后，把它双击丢给本工具自己就能装（`.AppImage` 分支会
认出 `usr/share/applications/` 里的桌面入口和 hicolor 图标）—— 这是
`build-appimage.sh` 里那两份 `.desktop` 和图标目录存在的原因，别精简掉。

## 7. 不要做的事

| 别做 | 原因 |
|---|---|
| 删掉 `build_arch_pkg` 里的打包自检 | 那是被 `bsdtar -n` 坑逼出来的。误加 `-n` 会打出**空包且不报错** |
| 把 `usage()` 的 `sed -n '3,13p'` 改成别的行号而不核对 | 三个脚本用行号提取头部注释，移动行号会让 help 输出错乱 |
| 往 stderr 写正常信息 | GUI 合并 stderr 到 stdout，块缓冲会让行序全乱（源码注释里有说明） |
| 把 GUI 的 shebang 改成 `env python3` | `gi` 装在系统 python 下。走 `env` 可能命中无 `gi` 的解释器 → 直接崩 |
| 把 `"@PREFIX_BIN@" in cand` 直写成字面量 | 安装时的 `sed` 会把这行也替换掉，反而跳过正确路径。**标记必须拼开写**（`_PH = "@PREFIX_" + "BIN@"`） |
| 移除钩子改成默认开启 | `prerm`/`postrm` 在卸载时以 root 执行，而用户那时早忘了安装期的警告。这是刻意的保守取舍 |
| 在 `_db_run` 里去掉 `>/dev/null 2>&1` | 外来脚本的输出会污染 GUI 的解析流 |
| 在 `_db_run` 里去掉 `\|\| true` | Debian 脚本在 Arch 上注定部分失败（依赖不存在的东西），强制成功会让正常包装不上 |
| 让 `analyze_deb` 直接 `die` | 现在它只报告不阻断，是刻意的（GUI 需要完整报告）。要阻断请加 `--strict` |
| 把 `[ -t 0 ]` 当成"有人看着" | 它是"stdin 是终端"。GUI 和管道下都为假。**绝不能把"问不出来"当成"用户同意"** |
| 执行外来 AppImage（哪怕只是"跑一下看看"） | 那是不可信二进制，执行一次等于让对方在你机器上任意执行。只能用 `file`/`7z` 读 |
| 拿 AppImage 根目录的 `.desktop`/`.png` 当真身 | 那些是指向 `usr/share/` 的符号链接，抽出来只有一行链接目标 |
| 删掉 AppImage 确认框里"无法审查"那段 | 这条路径没有高危门禁，那句是唯一的风险披露 |
| 把 `.AppImage` 的处理塞进 `debinstall` 引擎 | 引擎的三步（审计脚本/解析依赖/转 Arch 包）对 AppImage 一步都不适用，只会搅浑 `MODE` 状态机 |

## 8. 排障

### 依赖解析结果为空（`缺失库` 一堆，或一条映射都没有）

99% 是 `pacman -F` 用不了：

```bash
ls /var/lib/pacman/sync/*.files     # 空 → 就是这个问题
sudo pacman -Fy
```

### GUI 起不来 / 一打开就退

```bash
deb-install-ui                      # 直接在终端跑，看报错
/usr/bin/python3 -c 'import gi; print("gi ok")'
```

`ModuleNotFoundError: No module named 'gi'` → `sudo pacman -S python-gobject gtk3`。

如果是"找不到 deb-install 工具" → GUI 的 `find_tool()` 没找到引擎。检查：

```bash
which deb-install
echo $DEB_INSTALL_TOOL
grep -n 'PREFIX_BIN\|deb-install",' ~/.local/bin/deb-install-ui
```

### GUI 里点安装，密码框不弹

引擎在无 tty 时会设 `SUDO_ASKPASS` 指向 `~/.local/bin/deb-install-askpass`。
检查该文件存在且可执行：

```bash
ls -l ~/.local/bin/deb-install-askpass
echo $SUDO_ASKPASS
```

### 转换失败：打包自检报"源树 N 个条目，包里只有 M 个"

几乎肯定是打包命令里混进了 `-n`（见 `DESIGN.md` §5.4.4）。
检查 `$WORK/_build.sh` 的生成模板里那两个 `bsdtar` 调用。

### `pacman -U` 报文件冲突

正常现象（Debian 和 Arch 对同一文件归属不同包）。两条出路：

```bash
debinstall -l <pkg.deb>              # 装到 ~/.local，不冲突
debinstall --overwrite <pkg.deb>     # 明确允许覆盖（先看清冲突清单）
```

### 本地安装后命令能点到但一跑就报"没有那个文件或目录"

已知局限（`DESIGN.md` §5.7.1）。包里的脚本按绝对路径调同包的其它文件，
本地模式下那些路径不存在。工具会主动提示。改用 `--install`。

### 卸载后桌面图标/命令还在

- 路线 B：`debinstall -R <名>` 读 `.debinstall-manifest` 逐个删。
  若 manifest 丢了，手动删 `~/.local/bin/<名>` 和 `~/.local/debinstall/<名>/`
- 路线 A：`pacman -R <名>`
- 路线 C：`deb-install-raw --uninstall <名>`

### 桌面快捷方式没出现

```bash
xdg-user-dir DESKTOP                # 目录存在吗
ls ~/Desktop
```

`make_desktop_shortcut` 依赖 `xdg-user-dir`（来自 `xdg-user-dirs`）。
没有就用 `~/Desktop`。另外包里必须**有 `.desktop`** 文件才会建。
